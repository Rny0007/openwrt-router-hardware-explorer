1. Initial Diagnosis & Fault Matrix

Before connecting hardware probes or flashing recovery images, systematically classify the router's hardware failure mode:

Observable Symptom Hardware Subsystem Status Suspected Root Cause Recommended Tier
Solid Red / Dark LED Bootloader BL2 not executing Corrupted SPI-NAND partition table or damaged BL2 header Tier 4 / Tier 5
Flashing Rapid Pulse (Heartbeat) Linux Kernel booting; LuCI offline Firewall misconfiguration or uhttpd service crash Tier 1 (Failsafe)
Link Flapping (5-8s cycle) U-Boot watchdog resetting kernel Kernel panic during rootfs mount (UBI corrupted) Tier 2 / Tier 3
No Ping to 192.168.1.1 Network stack uninitialized or subnet mismatch Host adapter IP configured on wrong subnet (e.g. 192.168.0.x) Tier 1 / Static IP

3. Required Tools & Bench Prerequisites

LOGIC LEVEL SAFETY WARNING: Always verify that your USB-to-UART adapter is set to 3.3V TTL mode via physical jumper or switch. Standard 5V FTDI or RS-232 (+12V/-12V) adapters will overvoltage and permanently destroy the SoC GPIO silicon.

Hardware Equipment

  • USB-UART Adapter: CP2102, FT232RL, or CH340G with physical 3.3V jumper set.
  • Dupont Jumper Wires: Female-to-female and female-to-male test leads.
  • Cat6 Ethernet Cables: Direct host-to-router connection (LAN1).
  • Uninterruptible Power Supply (UPS): Ensures stable voltage during flash operations.
  • Digital Multimeter: Verify 3.3V logic level between TX and GND before connecting.

Software Utilities

  • Serial Console: PuTTY (Windows) or picocom / minicom (Linux).
  • TFTP Server: Tftpd64 portable (Windows) or tftpd-hpa (Linux).
  • OpenSSH Client: Pre-installed on Windows PowerShell 10+ and Linux.
  • Recovery Kernel: Official OpenWrt *-initramfs-recovery.bin image.

4. Mandatory Partition Preservation Protocol

DO NOT OVERWRITE CALIBRATION PARTITIONS: The vendor Factory and MFG partitions contain cryptographically signed RF calibration values and physical MAC address labels tuned specifically to your device's RF front-end module. Erasing them causes irreversible Wi-Fi power degradation (dropping signal by up to 15 dBm).

Whenever terminal access or failsafe shell is available, immediately archive all MTD partitions:

# [Router Terminal]
cat /proc/mtd
dd if=/dev/mtd0 of=/tmp/mtd0_fullchip_backup.bin bs=128k
dd if=/dev/mtd3 of=/tmp/mtd3_Factory.bin
dd if=/dev/mtd7 of=/tmp/mtd7_MFG.bin

5. The Five Recovery Tiers

Tier 1: OpenWrt Failsafe Mode

If OpenWrt boots but custom firewall rules or network settings lock out web/SSH access, enter failsafe mode:

  1. Set PC Static IP: 192.168.1.2 (Subnet 255.255.255.0). Connect cable to router LAN1.
  2. Power cycle router. When the front LED flashes rapidly, press the physical RESET button once.
  3. Open terminal and execute:
ssh -o StrictHostKeyChecking=no root@192.168.1.1
mount_root
firstboot -y
reboot -f

Tier 2: OEM Web Failsafe Interface

MediaTek Filogic and GL.iNet bootloaders feature an embedded HTTP server in U-Boot:

  1. Set PC static IP to 192.168.1.2. Connect to LAN1.
  2. Power on the router while holding down the RESET button for 8 to 10 seconds.
  3. Navigate to http://192.168.1.1 in your web browser. Upload the official OpenWrt sysupgrade binary.

Tier 3: Automated Bootloader TFTP Client Mode

When rootfs cannot mount, the bootloader broadcasts TFTP requests to predefined IP addresses:

Platform / Vendor Router Target IP Host PC TFTP Server IP Required Image Filename
MediaTek Filogic (U-Boot) 192.168.1.1 192.168.1.254 (or 192.168.1.10) openwrt.bin / recovery.bin
TP-Link MediaTek 192.168.0.1 192.168.0.66 ArcherC6v3_tp_recovery.bin
Xiaomi / Redmi 192.168.31.1 192.168.31.100 test.bin
Netgear WAX206 192.168.1.1 192.168.1.10 wax206.img 
# Linux TFTP Server Setup
sudo apt install tftpd-hpa
sudo cp openwrt-*-initramfs.bin /var/lib/tftpboot/openwrt.bin
sudo systemctl restart tftpd-hpa

Tier 4: Hardware 3.3V TTL Serial UART Console

CRITICAL ELECTRICAL RULE: Connect ONLY GND, TX, and RX. NEVER CONNECT THE VCC PIN from your USB-UART adapter. Doing so causes power back-feeding and can permanently destroy the SoC. 
USB-UART Adapter                Router PCB Serial Header
[ GND ] ------------------------ [ GND ] (Ground reference)
[ RX  ] ------------------------ [ TX  ] (Crossover transmit)
[ TX  ] ------------------------ [ RX  ] (Crossover receive)
[ VCC ] (DISCONNECTED)           [ VCC ] (STRICTLY DISCONNECTED)

Open PuTTY (Windows) or picocom (Linux) at 115200 baud, 8 data bits, 1 stop bit, no parity (8N1). Power cycle the router and repeatedly press Space or Enter to interrupt autoboot into the U-Boot console: 

# Configure network inside U-Boot
setenv ipaddr 192.168.1.1
setenv serverip 192.168.1.254
ping 192.168.1.254

# Load initramfs recovery kernel into DDR RAM
tftpboot 0x46000000 openwrt-initramfs.bin
fdt addr \$(fdtcontroladdr)
fdt rm /signature
bootm 0x46000000

Tier 5: External Hardware Flash Programmer

When the SPI-NAND bootloader partitions (`BL2`, `FIP`) are completely erased or corrupted, attach a CH341A or T48 external hardware programmer with a SOIC8/WSON clip directly to the flash chip: 

# Flash raw fullchip dump to SPI chip
flashrom -p ch341a_spi -w mtd0_fullchip_backup.bin

7. Success Verification Protocol

After executing recovery procedures, verify operational health in this exact sequence:

  • ICMP Echo Response: ping 192.168.1.1 responds consistently with round-trip times < 1.0 ms and 0% packet loss.
  • LuCI Web Interface: Open http://192.168.1.1 in an incognito browser window and confirm OpenWrt login banner renders.
  • SSH Authentication: ssh root@192.168.1.1 connects cleanly without Dropbear host key errors.
  • Kernel dmesg Audit: Run dmesg | grep -iE "fail|error|panic" to ensure no persistent hardware driver crashes.

8. Common Recovery Failures & Resolutions

Symptom Root Cause Corrective Action
TFTP server log shows no file requests Host PC static IP configured on wrong network or firewall blocking UDP port 69 Disable Windows Defender Firewall temporarily; verify Ethernet cable is plugged into LAN1
Serial terminal outputs garbled ASCII characters Baud rate mismatch or missing ground connection Confirm baud rate is 115200 (or 1500000 for RK3568); confirm adapter GND is firmly bonded to router PCB GND
Router loops repeatedly after TFTP transfer Kernel image is incompatible or missing initramfs ramdisk payload Ensure you are flashing the initramfs-recovery.bin image, NOT a standard squashfs sysupgrade image

9. Electrical Safety & Risk Protocol

ESD & GROUNDING ADVISORY: Work on a static-dissipative ESD mat with a wrist strap attached to ground before touching exposed router circuitry. High ESD potentials can latch up sensitive transceiver silicon.
  • Voltage Rail Verification: Router serial logic is strictly 3.3V TTL. Never connect 5V TTL or RS-232 (+12V/-12V).
  • VCC Prohibition: The VCC pin from your serial adapter must remain completely disconnected. Power the router solely from its own DC power adapter.
  • Electrostatic Discharge (ESD): Work on an anti-static mat and touch a grounded metal chassis before handling open router PCBs.
  • Capacitor Discharge: Wait a minimum of 10 seconds after unplugging the router before attaching or removing serial probes.
