Hardware Research & Verification Methodology

The evidentiary standards and verification taxonomy governing all repository records.

Primary Evidentiary Hierarchy

No device record, chipset specification, or recovery procedure is published without corroboration from primary sources:

  1. Upstream OpenWrt Git Repository: Device tree DTS files, image makefiles, and Git commit logs.
  2. Official FCC ID Filings: Internal teardown photography, RF shielding inspection, and component silkscreen decoding.
  3. Physical UART Boot Captures: Reproducible U-Boot console logs, dmesg outputs, and MTD partition tables.
  4. Vendor GPL Source Tarballs: Bootloader configurations, kernel trees, and hardware revision errata.

Strict Status Taxonomy

StatusDefinition & Evidence Requirement
OFFICIALLY_SUPPORTEDDevice is formally merged in upstream OpenWrt Git master or stable releases. Official firmware selector download link exists.
COMMUNITY_VERIFIEDDevice boots and runs OpenWrt via functional community build with reproducible boot logs and physical hardware confirmation.
PARTIALLY_VERIFIEDDevice boots OpenWrt, but major subsystems (e.g. proprietary Broadcom Wi-Fi transceivers) are non-functional due to driver constraints.
UNSUPPORTEDHardware cannot run OpenWrt due to BootROM signature locks, proprietary bootloader encryption, or missing architecture support.
